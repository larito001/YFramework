# 模块规范

> 范围：Framework 各模块的职责、对外 API、扩展约定、典型用法。
> 业务模块（GamePlay/）只在最后一节简述，业务侧实现细节随业务演进，不写死规范。

---

## 0. 总览

```
            ┌──────────────────┐         ┌─────────────────────┐
            │   GameLoop (MB)  │         │ YNetworkManager (MB)│  ← 挂在 Scene
            └────────┬─────────┘         └──────────┬──────────┘
                     │ AddComponent 各 Mgr           │ Mirror lifecycle
                     │ + 注册到 GameContext          │
            ┌────────▼─────────┐                     │
            │    GameContext   │  ← Service Locator  │
            │   (POCO 查找表)   │ ◄── EventMgr ──────┘  (转发网络事件)
            └──────────────────┘
                     ▲
                     │ 各 Mgr 都是 MonoBehaviour, 挂在 GameLoop GO 上
                     │ 用 Unity 原生 Awake / Update / OnDestroy
   ┌─────┬─────┬─────┴─────┬─────┬─────┬─────┐
   ▼     ▼     ▼           ▼     ▼     ▼     ▼
  Res   UI   Sound      Camera Event Store  ...

NetworkBehaviour 不进 GameContext，由 Mirror prefab spawn 管理：
  NetworkEntityBase → NetworkBehaviour（Player / Enemy / Bullet / ...）
```

- 各 Mgr 都是 `MonoBehaviour`，由 `GameBootstrapper.BuildContext` 在 GameLoop 同一个 GameObject 上按依赖顺序 `AddComponent` 并 `ctx.Register`。AddComponent 顺序 = Awake 顺序。
- 生命周期走 Unity 原生：`Awake`（拿依赖+初始化）/ `Update`（如需帧驱动）/ `OnDestroy`（清理）。不再有 `IGameService` / `ITickable` 这套平行接口。
- `GameContext` 退化为纯 Service Locator，仅做 Register / Get / TryGet。
- 网络层：`YNetworkManager`（Mirror NetworkManager 子类）独立挂在 Unity Scene 中，通过 `GameLoop.Instance.Ctx` 反向访问 `EventMgr` 转发生命周期事件。
- 场景：Unity 原生 Scene 资产 + `SceneManager.LoadScene` / `NetworkManager.ServerChangeScene`，详见 §7。
- 联网实体：继承 `NetworkEntityBase`，由 Mirror spawn 管理，详见 §17。

## 1. GameContext（Service Locator）

**位置**：`Framework/GameContext/GameContext.cs`
**职责**：服务注册与类型安全解析。不再做生命周期或帧驱动。

### 对外 API

```csharp
T   Get<T>()                  // 不存在抛异常
bool TryGet<T>(out T)         // 容错获取
void Register<T>(T instance)  // 重复注册抛异常
```

### 扩展约定

- **新增框架服务**：在 `GameBootstrapper.BuildContext` 内部 `ctx.Register(go.AddComponent<XxxMgr>())`（被依赖者在前）。
- **新增业务服务**：在 `GameProjectBootstrapper.RegisterProjectServices(ctx)` 内 `ctx.Register(loop.gameObject.AddComponent<YyyMgr>())`。
- 服务必须是 `MonoBehaviour`；自己在 `Awake` 里拿依赖（`GameLoop.Instance.Ctx.Get<XXX>()`），需要帧驱动直接用 `Update / FixedUpdate / LateUpdate`。

## 2. GameLoop / GameBootstrapper

**位置**：`Framework/GameContext/GameLoop.cs`、`GameBootstrapper.cs`、`GamePlay/GameProjectBootstrapper.cs`

**职责**：
- `GameLoop`：MonoBehaviour 入口。`Awake` 时创建 `Ctx`，调 `GameBootstrapper.BuildContext(this, Ctx)` 在自身 GO 上 `AddComponent` 各 Mgr 并 Register。**不再做 Tick/FixedTick/LateTick 转发**。
- `GameBootstrapper`：`partial static`。Framework 写死框架服务注册顺序；业务通过三个 `partial` 方法插入：

```csharp
static partial void RegisterProjectServices(GameContext ctx);
static partial void ConfigureProjectUi(UIConfig uiConfig);
static partial void RunProjectStartup(GameContext ctx);
```

**关键约定**：

- AddComponent 顺序 = Awake 顺序 = 依赖图拓扑序。被依赖者必须先 AddComponent。
- 任何 Mgr 在 `Awake` 里访问 `GameLoop.Instance.Ctx.Get<Dep>()` 时，前置依赖必须已经 AddComponent（即先 Register）。
- 需要 **构造参数** 的 Mgr（如 `UIMgr` 需要 `UIConfig`）：暴露 `Initialize(...)` 方法，`BuildContext` 在 AddComponent 后立即调。
- `RunProjectStartup` 是业务首屏入口（当前为 `Show<StartPanel>()`），不要在 `RegisterProjectServices` 里调 UI / 触发资源加载。

## 3. CoroutineRunner

**位置**：`Framework/GameContext/CoroutineRunner.cs`
**接口**：`ICoroutineRunner { Coroutine Run(IEnumerator); void Stop(Coroutine); }`
**注册形式**：`MonoBehaviour`，挂在 `GameLoop` 同一 GameObject 上（`BuildContext` 自动 `AddComponent`）。

**用法**：需要协程的 Mgr 在 `Awake` 里 `GameLoop.Instance.Ctx.Get<ICoroutineRunner>()` 缓存引用，`OnDestroy` 置空。**禁止**业务自己挂额外 MonoBehaviour 起协程。

## 4. 事件系统 EventMgr

**位置**：`Framework/Event/EventMgr.cs`（业务枚举见 `GamePlay/Event/GameEventTypes.cs`）
**职责**：类型安全的全局事件，泛型最多 4 参数；同回调防重复订阅。事件键为任意 `System.Enum`，框架不绑定具体业务枚举。

### API

```csharp
// 订阅 / 反订阅（0–4 参数泛型重载）
void Add<T1,T2>(Enum type, Action<T1,T2> callback)
void Remove<T1,T2>(Enum type, Action<T1,T2> callback)

// 触发
void Trigger<T1,T2>(Enum type, T1 a, T2 b)

void Clear()
```

调用时直接传枚举值（如 `YOTOEventType.RefreshBagList`），编译期推导类型；`Enum` 仅作内部 dictionary 键。

### 实现关键

- 内部用 `Dictionary<Enum, IEventSlot>` + `EventSlot<TDelegate>` 持有委托。
- 订阅时类型不匹配会 `LogError`（同一事件键一旦确定参数签名，后续订阅必须一致）。
- 反订阅后若槽位为空自动移除，避免内存膨胀。

### 约定

- **生命周期**：UI 页面 `OnShow` 订阅、`OnHide` 反订阅；服务 `Init` / `Shutdown`。
- **不要** 用匿名 lambda 直接订阅（无法准确反订阅）；用具名方法或 `Action` 字段。
- 多于 4 参数 → 定义结构体作为单参传入。
- 业务枚举集中在 `GamePlay/Event/GameEventTypes.cs`（当前文件中的 `YOTOEventType`），新业务事件加在那里；不要在框架 `Framework/Event/` 下定义业务事件。

## 5. 资源管理 ResMgr

**位置**：`Framework/Res/ResMgr.cs`
**职责**：基于 `Resources.Load` 的引用计数 + 异步加载 + `ResourceHandle<T>` 自动释放。

### API

```csharp
T Load<T>(string path)                           // 同步，计数 +1
void LoadAsync<T>(string path, Action<T> cb)     // 异步，计数 +1
ResourceHandle<T> LoadHandle<T>(string path)     // 同步，返回 handle（推荐）
void LoadHandleAsync<T>(string path, Action<ResourceHandle<T>> cb) // 异步 + handle
void Release<T>(string path)                     // 计数 -1
void ReleasePack(string path, Object obj = null) // 按对象类型自动 Release
IEnumerator OnChangeScene(Action cb)             // 切场景时清理（YSceneManager 自动）
```

### `ResourceHandle<T>`

- `IDisposable`，`using` 块内自动 `Release`。
- 持有 `Path`、`Asset`、`IsReleased`。
- 子系统 (`UIPageHandler`、`SoundMgr`、`ObjectPool.PoolBuffer`) 全部用 handle，确保资源生命周期可追踪。

### 关键不变量

- 资源以 `(path, Type)` 作为缓存 key。同 path 但不同类型加载产生独立条目。
- 异步加载未完成期间多次请求合并为同一 coroutine + pending callbacks，不会重复发起 `LoadAsync`。
- `Resources.UnloadAsset` 不能用于 `GameObject`/`Component`，所以 GameObject 释放时只是从缓存移除并标记 `pendingUnusedAssetSweep`，由下次 `OnChangeScene` 调用 `Resources.UnloadUnusedAssets` 完成。

### 约定

- **始终通过 ResMgr**，不直接 `Resources.Load`。
- 加载失败：API 返回 `null`，调用方判空。
- 不缓存 `ResourceHandle.Asset` 字段超过 handle 生命周期。

## 6. UI 系统

**位置**：`Framework/UI/UIMgr.cs`、`UIConfig.cs`、`UIPageBase.cs`、`UIPageHandler.cs`、`Components/`

### 6.1 分层

5 层 Canvas（`UILayerEnum`），渲染顺序由低到高：

| 层 | sortingOrder | 用途 |
|---|---|---|
| `Normal` | 0 | 主界面、面板（StartPanel、GameMainPanel） |
| `Top` | 100 | 普通弹窗 |
| `RayCast` | 200 | 阻挡输入的全屏遮罩（LoadingPanel 当前在此层） |
| `Tips` | 300 | 提示弹窗 |
| `PopText` | 400 | 飘字（FlyText） |

每层独立 `Canvas` + `CanvasScaler`（1920×1080 参考分辨率，`MatchWidthOrHeight=0`）+ `GraphicRaycaster`。

### 6.2 注册流程

业务在 `GameProjectBootstrapper.ConfigureProjectUi` 中注册：

```csharp
uiConfig.RegisterLoading<LoadingPanel>(UIEnum.LoadingPanel, UILayerEnum.RayCast, "UI/LoadingPanel", 0f);
uiConfig.Register<StartPanel>(UIEnum.StartPanel, UILayerEnum.Normal, "UI/StartPanel");
```

参数：枚举 / 层级 / Resources 路径 / 关闭后销毁延迟（秒）。`closeDestroyDelay <= 0` 表示不自动销毁。

### 6.3 显示 / 隐藏

```csharp
// 通过容器
var ui = ctx.Get<UIMgr>();
ui.Show<StartPanel>();
ui.Show<MyPanel>(myParam);
ui.Hide<MyPanel>();
ui.ShowLoading();
ui.HideLoading();
ui.IsShown(UIEnum.StartPanel);
ui.TryGetPage<StartPanel>(out var page);

// 在 UIPageBase 内
Show<MyPanel>();
CloseSelf();
```

### 6.4 页面生命周期

```
预制体 prefab 异步加载
        ↓
Initialize(context, manager)   // 注入依赖
        ↓
OnLoad()                       // 一次性绑定
        ↓
BeforeShow(param) / OnBeforeShow<TParam>
        ↓
OnShow()                       // 订阅事件、刷新数据
        ↓
   ...展示中...
        ↓
OnHide()                       // 反订阅、停 Tween
        ↓
（closeDestroyDelay 后）
Destroy()                      // 销毁 GameObject、Release prefab handle
```

`OnResize` 在屏幕分辨率变化时（`ScreenMonitor.OnScreenResize` → `UIMgr.ResizeScreen`）逐页调用。

### 6.5 UIPageBase

- `Awake` 自动收集所有 `YOTOUIChangeBase` Tween（`YOTOUIShow` 等），`Enter`/`Exit` 时统一播放。
- `RequireComponent(typeof(CanvasGroup), typeof(YOTOUIShow))`：预制体 **必须** 挂这两个组件。
- 泛型版 `UIPageBase<TParam>`：自动把 `BeforeShow(object)` 转换为 `OnBeforeShow(TParam)`，类型不匹配会 `LogError`。

### 6.6 复用组件（`Components/`）

| 组件 | 用途 |
|---|---|
| `YOTOButton` | 含悬停/点击缩放 + 文字颜色三态的按钮，配 `YOTOButtonEditor` |
| `YOTOScrollView` | 池化滚动列表（垂直/水平/Grid） |
| `YOTOScrollViewItem` | 列表 item 基类 |
| `YOTOUIShow` | CanvasGroup 渐显/渐隐（`OnEnter`/`OnExist`） |
| `YOTOUIMove` | 位置移动型动画 |
| `YOTOUIChangeBase` | 上述动画的抽象基类 |

### 6.7 屏幕监听

`ScreenMonitor : ITickable` 每帧比较 `Screen.width/height`，变化时触发 `OnScreenResize` 事件，业务可订阅或交给 `UIMgr.ResizeScreen` 自动处理。

### 6.8 飘字 FlyText

**位置**：`Framework/UI/FlyText/`（`FlyTextMgr.cs`、`FlyTextCtrl.cs`）。

- `FlyTextMgr : IGameService, ITickable` —— 在 `BuildContext` 中作为框架服务注册，每帧最多生成 `generateNumPerFrame` 个飘字，超量入队等待。
- `FlyTextCtrl : ObjectBase, PoolItem<Transform>` —— 单条飘字实体，复用 `DataObjPool`，飘字结束自动回池。
- 业务调用：

```csharp
var fly = ctx.Get<FlyTextMgr>();
fly.AddText("hit!", worldPos);                           // 默认 Normal，世界坐标
fly.AddTextAtScreenCenter("CRITICAL", FlyTextType.Quick);
```

- 飘字预制体路径硬编码 `UI/FlyText/FlyTextPrefab`（在 `FlyTextCtrl.SetData`），实际位于 `Resources/UI/FlyText/FlyTextPrefab.prefab`。
- `FlyTextType` 决定颜色与动画风格（`Normal/Quick/PlayerHurt/AddHP`）。

## 7. 场景管理

**位置**：`Framework/Scene/`、业务侧 `GamePlay/Scene/`

> 旧 `YSceneManager` / `YSceneBase`（基于 GameObject SetActive 的逻辑场景）已退役。所有场景都是真实的 Unity Scene 资产，通过 Unity 原生 `SceneManager.LoadScene` 或 Mirror `NetworkManager.ServerChangeScene` 切换。

### 7.1 场景常量

业务侧 Unity Scene 资产名集中在 `GamePlay/Scene/GameSceneTypes.cs`：

```csharp
public static class YSceneNames
{
    public const string Start = "GameStart";   // 引导场景
    public const string Main  = "GameMain";    // 玩法场景
}
```

新增场景：加一个 const string，对应 `.unity` 资产加到 Build Settings。

### 7.2 场景引导脚本

每个 Unity Scene 资产的根节点上挂一个 MonoBehaviour，负责该场景的本地初始化（UI 显示、敌人生成等）：

```csharp
public class GameMainScene : MonoBehaviour
{
    private void Start()
    {
        var ctx = GameLoop.Instance?.Ctx;
        if (ctx == null) return;
        // 业务初始化：ctx.Get<UIMgr>().Show<GameMainPanel>(); 等
    }
}
```

`Start` 阶段所有 `Awake` 已结束，`GameLoop.Ctx` 必已就绪。

### 7.3 切场景

- 单机：`UnityEngine.SceneManagement.SceneManager.LoadScene(YSceneNames.Main)`
- 联网：`NetworkManager.singleton.ServerChangeScene(YSceneNames.Main)`（仅 server 可调，所有 client 会跟随）

切场景完成后框架自动做：
- `SceneReferenceService` 订阅 `SceneManager.sceneLoaded` → `InvalidateCache`
- 业务侧无需手工触发

### 7.4 SceneReferenceProvider / Service

**思路**：场景里需要被代码访问的 Transform / Light，挂 `SceneReferenceProvider`（key→Transform 列表），通过 `SceneReferenceService.TryGetTransform(key, ...)` 取。失败兜底 `GameObject.Find`。

**使用规则**：

- 框架级 key 常量定义在 `Framework/Scene/SceneRefKeys.cs` 的 `SceneRefKeys` 类（`MainCamera`、`MainCameraVirtual`、`MainLight`、`AStarRoot`）。
- 业务级 key 定义在 `GamePlay/Scene/GameSceneReferenceKeys.cs` 的 `GameSceneRefKeys` 类（`PlayerSpawn`、`Spline`），按需新增。
- 新代码不要用 `GameObject.Find`，用 Provider。

## 8. 数据对象池 DataObjPool

**位置**：`Framework/Pool/DataObjectPool.cs`、`BaseEntity.cs`

> 旧 `ObjectPool` / `ObjectBase` / `SceneModelBase`（GameObject 池化 + 转发链）已退役。如果需要 GameObject 池化：联网对象走 Mirror `NetworkServer.Spawn`，纯本地表现自行写简单 `Stack<MonoBehaviour>`（参考 `FlyTextMgr`）。

### 8.1 DataObjPool<T, S>

纯 C# 对象池（无 GameObject）。适合"高频创建销毁的纯逻辑对象"。

```csharp
public static DataObjPool<MyEntity, MyData> pool =
    new DataObjPool<MyEntity, MyData>("MyEntity", capacity: 4);

var item = pool.GetItem(myData);  // 命中率统计 HitRate
pool.RecoverItem(item);
```

`T` 必须实现 `PoolItem<S>`：

```csharp
public interface PoolItem<S>
{
    void AfterIntoObjectPool();   // 入池前重置
    void SetData(S serverData);    // 取出时填数据
}
```

### 8.2 BaseEntity

DataObjPool 中可选的基类：
- `_entityID` — 自增 id
- `Init()` / `RemoveThis()` 钩子（被 DataObjPool 自动调用）
- `YOTOOnload()` / `YOTOOnHide()` 子类重写

框架内 A* 寻路的 `YAStarSeeker / YAStarLinker / YAStarObstacle` 使用这套。

### 8.3 何时用 DataObjPool

- 高频创建（>50/s）的临时数据对象 → 用池
- 一次性、低频创建 → 直接 new，让 GC 处理
- GameObject 池化 → 见上方提示

## 9. 音频 SoundMgr

**位置**：`Framework/Sound/`

**通道**：`SoundChannel { Master, Music, Sfx, Ui }`，4 通道独立音量与静音。
- Music：1 路 `AudioSource`，交叉淡入淡出（默认 0.15s）。
- SFX：1–16 路（按需扩到 `MaxSfxEmitters=16`）。
- UI：复用 SFX 池，但通道独立计算音量。

API：

```csharp
PlayBGM(path, volume)
StopBGM(fadeDuration = 0.1f)
PlaySFX(path, volume)
PlayUISFX(path, volume)
Play(path, SoundPlayOptions)         // 通用入口

PlayMusic(path, volumeScale, fadeDuration, restartIfSame, loop)
StopMusic(fade)
StopAllSFX(); StopAll();

GetChannelVolume(ch); IsChannelMuted(ch);
SetMasterVolume / SetBgmVolume / SetSfxVolume / SetUiVolume
SetMasterMuted / SetMusicMuted / SetSfxMuted / SetUiMuted
SetChannelVolume(ch, v); SetChannelMuted(ch, m);
```

设置变化自动通过 `SoundSettingsContainer : DataContaner<SoundSettingsData>` 持久化（key=`sound_settings`）。

**约定**：

- 资源路径必须在 `Resources/` 下，`SoundMgr` 内部用 `ResMgr.LoadHandleAsync<AudioClip>`，自动计数。
- `Stop*` 后 `AudioClip` handle 自动 release。
- BGM 在不同的 path 间切换会 `StopMusicTransition + SwapMusic` 协程，确保不会因网络/异步导致同时多个 music 在播。

## 10. 数据存储 StoreMgr

**位置**：`Framework/Store/StoreMgr.cs`

### 架构

```
DataContaner<T>  ←  业务定义存档结构
       │
       │ Save / Load
       ▼
   StoreMgr  ──→  ISaveStrategy  (默认 JsonSaveStrategy / Unity JsonUtility)
                 IStorageDriver  (默认 FileStorageDriver / persistentDataPath)
                       │
                       └─ ICoroutineRunner（异步 IO）
```

### 业务用法

```csharp
[Serializable]
public class MyData { public int level; }

public class MyContainer : DataContaner<MyData>
{
    private MyData data = new();
    public override string SaveKey => "my_save";
    public override MyData GetData() => data;
    public override void __SetData(MyData v) => data = v ?? new MyData();
}

// 在某个服务中：
var c = new MyContainer();
c.BindStore(ctx.Get<StoreMgr>());
c.Load(() => Debug.Log(c.GetData().level));
c.Save();
```

### 扩展

- 替换序列化器：实现 `ISaveStrategy`（如 MessagePack、Protobuf），改 `StoreMgr.Init` 内的策略实例。
- 替换存储介质：实现 `IStorageDriver`（如 PlayerPrefs、SQLite、云存储），同上。
- 默认存储路径：`Application.persistentDataPath/<saveKey>.json`。

## 11. 相机 CameraMgr / SceneInteractionService

**位置**：`Framework/Camera/`

### CameraMgr

- 通过 `SceneReferenceService` 解析 `MainCamera` 的 Transform。
- 缓存 Cinemachine `VirtualCamera` / `FreeLook`，按 name 取。
- 提供震屏 `ShakeCamera(duration, intensity)` + `UpdateShake(dt)`（由 `SceneInteractionService.Tick` 间接驱动）。
- `UseVirtualCamera = true` 时，`Init` 内自动给主相机加 `CinemachineBrain`、生成 `MainCameraVirtual`。

### SceneInteractionService

`ITickable`，每帧只做一次 `Physics.Raycast` 缓存命中物，分发：

- 悬停 → `IHoverable.OnHover/OnHoverExit`
- 点击 → `IClickable.OnClick`（不超过拖拽阈值时）
- 拖拽 → `IDraggable.OnMouseDown/Drag/Up`（用平面投射避免出碰撞体中断）

UI 上方点击会 `EventSystem.IsPointerOverGameObject` 直接屏蔽，不进入场景交互。

排除层：自动忽略 `BulletTrigger` 层（如不存在则用 `DefaultRaycastLayers`）。

## 13. 状态机 YStateMachine

**位置**：`Framework/StateMachine/YStateMachine.cs`

简单分层状态机：

```csharp
interface IYState {
    string GetStateName();
    void EnterState(YStateMachine, object param);
    void UpdateState(YStateMachine, float dt);
    void ExitState(YStateMachine);
}

machine.SwitchState(newState, param);
machine.ReturnToPreviousState();   // 回到上一状态（携带原参数）
machine.Update(dt);                 // 由调用方驱动
machine.GetCurrentStateName();
```

**特点 / 约定**：

- 同状态重复 `SwitchState` 会 `LogError`，避免 enter/exit 失衡。
- `previousState` 仅保留一层，连续 `ReturnToPreviousState` 不可重入。
- 业务持有 `YStateMachine` 实例，通常在 ITickable.Tick 中转 `Update(dt)`。

## 14. 定时器 Timers

**位置**：`Framework/Time/TimeMgr.cs`

**单例**：`Timers.inst`（首次访问时自动创建 `[FairyGUI.Timers]` GameObject，`DontDestroyOnLoad`）。

```csharp
Timers.inst.Add(interval, repeat, callback, callbackParam);
// repeat = 0 → 无限循环；> 0 → 触发次数；当前实现的 ObjectPool 用 -1 也按无限算
Timers.inst.Add(0.5f, callback);            // 单次（默认 repeat=1）
Timers.inst.CallLater(callback);            // 0.001s 后一次
Timers.inst.AddUpdate(callback);            // 每帧
Timers.inst.Remove(callback);
Timers.inst.Exists(callback);
Timers.inst.StartCoroutine(routine);        // 内部 engine 执行协程
```

**注意**：

- 同一个 callback 多次 `Add` 会被合并为 1 个（更新 interval/repeat），不会叠加。
- `catchCallbackExceptions = true` 时回调异常会被捕获并 `LogError`，不影响其他定时器。
- 定时器使用 `Time.unscaledDeltaTime`，**不受 `Time.timeScale` 影响**。

## 16. 业务模块（GamePlay）概要

业务层不在框架规范覆盖范围内，仅给出已有约定：

### 16.1 TaskSystem

- `TaskDefinition` (`ScriptableObject`) 定义任务（id、目标、奖励），通过 `[CreateAssetMenu]` 在 Editor 创建。
- `TaskInstance` 运行时进度（`isActive` / `isCompleted` / `objectiveProgress`），可被 `JsonUtility` 序列化（用 `List<Entry>` 替代 `Dictionary` 以兼容序列化）。
- `TaskManager : IGameService` 提供 `StartTask`、`TryProgress`、`OnTaskStarted` 等事件。
- `ITaskCondition` 是判断"事件→进度"的可插拔逻辑（如 `SimpleKillCondition`）。
- 持久化暂用 `PlayerPrefs`，规划改为接入 `StoreMgr`。

### 16.2 业务 UI

- 命名以 `Panel` 结尾（`StartPanel`、`GameMainPanel`、`SettingPanel`、`FinishPanel`、`LoadingPanel`）。
- 复杂面板拆 Ctrl 子组件（参考 `SettingPanel` + `BaseSettingCtrl` / `AudioSettingCtrl` / `VideoSettingCtrl` / `GameSettingCtrl`）。
- 列表用 `YOTOScrollView` + 子类化 `YOTOScrollViewItem`。

### 16.3 业务场景

`GameStart` / `GameMain` 两个 Unity Scene 资产。新增场景：

1. `YSceneNames` 加 const string。
2. `Assets/Scenes/` 建对应 `.unity` 资产。
3. 写引导 MonoBehaviour（继承 `MonoBehaviour`，`Start` 时拿 `GameLoop.Instance.Ctx` 做事），挂到 scene 根节点。
4. `File → Build Settings → Scenes In Build` 加入。
5. 切换：单机 `SceneManager.LoadScene(YSceneNames.X)`；联网 `NetworkManager.singleton.ServerChangeScene(YSceneNames.X)`。

### 16.4 联网实体

业务联网对象（玩家、敌人、子弹）继承 `NetworkEntityBase`：

```csharp
public class MyPlayer : NetworkEntityBase
{
    [SyncVar] public int hp;

    [Command] public void CmdAttack(uint targetId) { /* server 执行 */ }
    [ClientRpc] public void RpcShowHit(Vector3 pos) { /* 所有 client 执行 */ }
}
```

prefab 必须挂 `NetworkIdentity`，按需配 `NetworkTransformReliable` 同步位置；prefab 配置到 `NetworkManager.playerPrefab` 或 `NetworkManager.spawnPrefabs`。详见 §17 与 `Docs/Mirror接入说明.md`。

## 17. 网络层 Mirror 集成

**位置**：`Framework/Network/`，Mirror SDK 在 `Assets/Plugins/Mirror/`

### 17.1 YNetworkManager

继承 `Mirror.NetworkManager`，重写生命周期钩子把事件转发到 `EventMgr`。挂在 Unity Scene 的 NetworkManager GameObject 上（通常配合 `KcpTransport`、`NetworkManagerHUD`）。

```csharp
public class YNetworkManager : NetworkManager
{
    public YNetworkMode Mode { get; }  // Offline / Server / Client / Host
}
```

### 17.2 网络事件

订阅通过 `EventMgr`，事件键定义在 `YNetworkEvent`：

| 事件 | 签名 | 触发时机 |
|---|---|---|
| `ServerStarted` / `ServerStopped` | `Action` | server 启停 |
| `ClientStarted` / `ClientStopped` | `Action` | client 启停 |
| `ServerSceneChanged` | `Action<string sceneName>` | server 完成场景切换 |
| `ClientSceneChanged` | `Action<string sceneName>` | client 完成场景切换 |

```csharp
ctx.Get<EventMgr>().Add(YNetworkEvent.ServerStarted, OnServerStarted);
ctx.Get<EventMgr>().Add<string>(YNetworkEvent.ServerSceneChanged, OnSceneChanged);
```

EventMgr 的事件签名一旦确定后续订阅必须一致。

### 17.3 NetworkEntityBase

联网实体基类（详见 §16.4 用法）。提供：
- `Ctx` — 拿 GameContext（与 GameLoop 共享）
- `GetService<T>` / `TryGetService<T>` — 拿 GameContext 内服务

直接继承 `NetworkBehaviour`，所有 `[SyncVar]` / `[Command]` / `[ClientRpc]` 由 Mirror Weaver 在编译期注入。

### 17.4 GameContext 与 Mirror 的边界

| 责任 | 归属 |
|---|---|
| 服务定位、本地服务生命周期 | GameContext |
| 帧驱动（ITickable / IFixedTickable） | GameLoop |
| 联网生命周期、SyncVar / Cmd / Rpc / spawn | Mirror NetworkBehaviour |
| 联网事件转发 | YNetworkManager → EventMgr |
| 网络场景流 | Mirror NetworkManager.ServerChangeScene |

不要把 `NetworkBehaviour` 注册进 `GameContext`（NetworkBehaviour 是 prefab 实例，生命周期不归 GameContext 管）。

### 17.5 配置与运行

详见 `Docs/Mirror接入说明.md`（NetworkManager 挂载、Player prefab 配置、Editor 启动验证）。
