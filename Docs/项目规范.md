### 1.0 角色—目录归属（团队协作准则）

| 目录 | 主要负责角色 | 说明 |
|---|---|---|
| `client/Assets/Art/**` | **美术** | 美术全权管理；程序只读引用，不增改不重命名 |
| `client/Assets/Resources/UI/**` | 美术 + 程序 | 预制体由 UI 美术拼装；程序按 §3.1 注册路径 |
| `client/Assets/Resources/Config/**` | 程序（自动生成） | `Data/*.bytes` 由配表工具产出；人工禁止改 |
| `client/Assets/Scenes/**` | 程序 + 关卡设计 | 业务场景搭建；编辑期资源走 `SceneReferenceProvider` |
| `client/Assets/Scripts/**` | **程序** | 严格分层（§1.1） |
| `client/Assets/ScriptGenerated/**` | 工具链 | 配表/Proto 自动生成 |
| `client/Assets/Plugins/**` | 程序 | 第三方 SDK；升级需走 PR |
| `client/Assets/ResourcesAssets/**` | 程序 | AB 包预留 |
| `ArtSource/**`（仓库根，Unity 工程外） | 美术 | PSD/AI/FBX/Blend 源文件；建议 Git LFS |

### 1.1 `Assets/Scripts/` 分层

```
Scripts/
├── Framework/      # 框架核心，业务无关。**禁止反向依赖 GamePlay/**
│   ├── GameContext/   # DI 容器、GameLoop、IGameService、CoroutineRunner
│   ├── Camera/        # CameraMgr、SceneInteractionService
│   ├── Config/        # ConfigManager（partial 类，由 ScriptGenerated/Config 扩展）
│   ├── Event/         # EventMgr（接受任意 Enum 作为事件键，业务枚举见 GamePlay/Event）
│   ├── PathFinding/   # A* 封装（YAStarManager 等，目录 com.arongranberg.astar.extension）
│   ├── Pool/          # ObjectPool / DataObjPool / ObjectBase / SceneModelBase
│   ├── Res/           # ResMgr（引用计数 + 异步加载）
│   ├── Scene/         # YSceneManager / YSceneBase / SceneReferenceService/Provider / SceneRefKeys
│   ├── Sound/         # SoundMgr / SoundTypes
│   ├── StateMachine/  # YStateMachine
│   ├── Store/         # StoreMgr / DataContaner / 存储驱动
│   ├── Time/          # Timers
│   ├── UI/            # UIMgr / UIPageBase / UIPageHandler / UIConfig / Components / FlyText
│   └── DontDestroy.cs
├── GamePlay/       # 业务层，可依赖 Framework/，不可被 Framework/ 反向依赖
│   ├── GameProjectBootstrapper.cs   # 业务接入点（partial 实现）
│   ├── Event/        # 业务事件枚举 GameEventTypes
│   ├── Particle/     # ParticleEntity（基于 ObjectBase 的业务粒子）
│   ├── Scene/        # GameMainScene / GameStartScene / GameSceneRefKeys
│   ├── TaskSystem/   # TaskManager / TaskDefinition / TaskInstance
│   └── UI/           # 各 *Panel / GameUIEnum
├── Editor/         # 编辑器扩展（CustomEditor、批处理工具）
└── Steamworks.NET/ # 第三方 Steam SDK 接入
```

**依赖方向（严格）**：`Editor → GamePlay → Framework → Unity / Packages`。任何 Framework→GamePlay 的引用都视为问题。

## 2. Unity 版本与依赖

| 项 | 版本/说明 |
|---|---|
| Unity | 2022.3 LTS |
| 渲染管线 | URP |
| 脚本运行时 | .NET Standard 2.1 / IL2CPP（按平台） |
| 目标帧率 | 60FPS（`GameLoop.Awake` 中 `Application.targetFrameRate = 60`） |

核心包/插件（详见 `Packages/manifest.json`）：

- **Cinemachine** — 虚拟相机管线，由 `CameraMgr` 集成
- **Universal RP** — 渲染管线
- **A* Pathfinding Project**（com.arongranberg.astar）— 寻路；扩展层在 `Framework/PathFinding/com.arongranberg.astar.extension/`
- **TextMeshPro** — UI 文本
- **DOTween** — 动画缓动（按钮悬停/UI 渐显等）
- **Entities / Burst / Mathematics** — 高性能计算（按需）
- **Steamworks.NET** — Steam 集成

升级 Unity 或核心插件版本必须：
1. 在 feature 分支单独提交；
2. PR 描述写清升级动机、影响面、测试覆盖；
3. 通过 `GameStart.unity` 完整跑一遍启动 → 进入 GamePlay 场景 → 退出，确认无报错。

## 3. 资源约定

### 3.1 路径与加载方式

| 资源类型 | 存放位置 | 加载入口 | 说明 |
|---|---|---|---|
| UI 预制体（启动/Loading） | `Resources/UI/Boot/**` | `UIMgr.Show<TPage>()` | 注册路径示例 `"UI/Boot/StartPanel"` |
| UI 预制体（主玩法） | `Resources/UI/Main/**` | 同上 | 路径示例 `"UI/Main/GameMainPanel"` |
| UI 预制体（设置） | `Resources/UI/Setting/**` | 同上 | 路径示例 `"UI/Setting/SettingPanel"` |
| UI 预制体（通用组件） | `Resources/UI/Common/**` | 同上 / `ResMgr` | 公共 Item / Button |
| 飘字 | `Resources/UI/FlyText/FlyTextPrefab` | `FlyTextCtrl` | 路径 `"UI/FlyText/FlyTextPrefab"` |
| 配表数据 | `Resources/Config/Data/*.bytes` | `ConfigManager.heroConfig.Get(id)` 等 | 自动生成，**禁止人工放入** |
| 寻路图 | `Resources/Config/Astar/*` | `YAStarManager.LoadPathFinding` | 路径基址 `Config/Astar/` |
| 音频 | `Resources/...`（按业务路径） | `SoundMgr.PlayBGM/PlaySFX` | 通过 `ResMgr` 引用计数管理 |
| 通用预制体 | `Resources/...` | `ResMgr.LoadHandleAsync` / `ObjectPool` | 走对象池或引用计数 |
| 美术原始资源 | `Art/`、`URP/` | 仅编辑期使用 | 不放进 `Resources/` 避免打包膨胀 |
| 待 AB 包资源 | `ResourcesAssets/**` | 未来 `AssetBundle.LoadFromFileAsync` | 当前不会被 `Resources.Load` 索引 |

**加载原则**：

- 优先 `LoadAsync` / `LoadHandleAsync`，避免主线程同步 IO。
- 同一资源使用同一 path 字符串，确保 `ResMgr` 引用计数命中同一缓存项。
- 任何 `Load`/`LoadHandle` 调用必须有对应的 `Release`/`Dispose`，否则资源不会卸载。
- 切场景时，`YSceneManager` 会触发 `ResMgr.OnChangeScene`（含 `UnloadUnusedAssets + GC`），不需手工调用。

### 3.2 命名

- 文件夹：`UpperCamelCase`（`Common/`、`Setting/`）。
- 预制体：业务前缀 + 用途，例如 `StartPanel.prefab`、`FlyTextPrefab.prefab`。
- 脚本一一对应 GameObject 时，名字保持一致。

## 4. 场景规范

### 4.1 启动场景

- `GameStart.unity` 是入口场景，必须挂 `GameLoop`（`DontDestroyOnLoad`）。
- `GameLoop.Awake` 调用 `GameBootstrapper.BuildContext` → `InitAll` → `RunStartup`，业务应在 `GameProjectBootstrapper.RunProjectStartup` 中决定首屏（当前为 `Show<StartPanel>()`）。

### 4.2 业务场景

- 每个业务场景实现 `YSceneBase`，重写 `SceneType`、`SceneName`、`OnEnterScene/OnLoadingEnd/OnLeaveScene`。
- 在 `GameProjectBootstrapper.ConfigureProjectScenes` 中 `RegisterScene<T>()` 完成注册。
- 切换：`ctx.Get<YSceneManager>().SwitchScene(YSceneType.GamePlay, args)`，默认会显示 `LoadingPanel` 并在切完后 GC。

### 4.3 场景引用

场景里需要被代码访问的 GameObject 必须由 `SceneReferenceProvider` 暴露：

```csharp
// 不允许：
GameObject.Find("MainCamera");

// 推荐：在场景里挂 SceneReferenceProvider，配置 key→Transform 映射
ctx.Get<SceneReferenceService>().TryGetTransform("MainCamera", out var camTransform);
```

`GameObject.Find` 仍在 `SceneReferenceService` 内做兜底，但仅作为最后手段，新代码请走 Provider。

## 5. 配表发布流程

### 5.1 工具链

```
excel/3xlsx/*.xlsx
    └─ python tools/publish_config.py
       ├─→ tools/_publish/proto/*.proto                    (proto 定义)
       ├─→ client/Assets/ScriptGenerated/Config/*.cs       (C# 解析类)
       ├─→ client/Assets/ScriptGenerated/Proto/*.cs        (protoc 输出)
       └─→ client/Assets/Resources/Config/Data/*.bytes     (运行时数据)
```

### 5.2 Excel 规则

- 表格放 `excel/3xlsx/`，文件名小写（`hero.xlsx`、`quest.xlsx`、`skill.xlsx`）。
- 每张表导出后产生 `<Pascal>Config` 类（`hero.xlsx`→`HeroConfig`），自动 partial 扩展到 `ConfigManager`。
- 跳过的文件配置在 `tools/tools_config.ini` 的 `[publish] skip_files`。
- 文件名以 `~` 或 `$` 开头（Excel 临时文件）会被自动跳过。

### 5.3 发布命令

```bash
# 全量发布
cd tools && python publish_config.py
# 或在仓库根
.\发布配表.bat

# 单表发布
.\tools\publish_single.bat hero
# 或
python tools/publish_config.py path/to/hero.xlsx
```

### 5.4 工具链依赖

- Python 3.10+
- `pip install protobuf grpcio-tools openpyxl`
- protoc：内置于 `tools/3rdparty/protobuf/protoc.exe`（Python 端用 `grpc_tools.protoc`，C# 端用此外置 protoc）

### 5.5 配表代码使用

`ScriptGenerated/Config/` 内的代码 **绝不手工修改**。表头变更后必须重发布。
访问示例：

```csharp
var hero = ctx.Get<ConfigManager>().heroConfig.Get(1001);
Debug.Log(hero.HeroName);
```

## 6. 构建与打包

> 本节为约定，当前仓库尚未提交 CI 脚本。

- 启动场景必须是 `GameStart.unity`，并放在 `Build Settings` 第 0 位。
- 打包前必须先发布配表，确保 `Resources/Config/Data/*.bytes` 与表头一致。
- 平台特定开关（Steam、移动等）放在 `ProjectSettings/`，不通过编辑器手改后再回退。
- 不要 commit `Library/`、`Temp/`、`obj/`、`Logs/` 等 Unity 生成目录（`.gitignore` 已覆盖）。

## 7. Git 工作流

- 主分支：`main`（保护，仅 PR 合并）。
- 当前业务分支：`T-Game`（实际开发分支，按特性切子分支后回合）。
- 命名：`feat/<feature>`、`fix/<bug>`、`refactor/<scope>`、`chore/<task>`。
- 提交信息中文/英文均可，但保持动宾结构、单条 ≤72 字（参考 `git log` 现有风格）。
- **禁止** 直接 push 到 `main`；**禁止** `--force` 推送任何远程分支。
- `.meta` 文件必须随脚本/资源同步提交，不要遗漏，否则其他成员会看到 GUID 漂移。
- 大型二进制（音频/视频/贴图原图）走 LFS 或外部存储，不直接进 Git。
