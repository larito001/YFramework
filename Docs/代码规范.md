# 代码规范

> 范围：C# 代码风格、命名、文件组织、注释、错误处理、性能、Unity 特定约定。
> 适用对象：`Assets/Scripts/Framework`、`Assets/Scripts/GamePlay`、`Assets/Scripts/Editor`。
> `Assets/ScriptGenerated/` 自动生成、`Steamworks.NET/` 第三方代码不受本规范约束。

---

## 1. 命名

### 1.1 类型与成员

| 元素 | 规则 | 示例 |
|---|---|---|
| 类 / 结构体 / 枚举 | `PascalCase` | `UIMgr`、`SoundEmitter`、`UILayerEnum` |
| 接口 | `IPascalCase` | `IGameService`、`ITickable`、`ICoroutineRunner` |
| 公开方法 / 属性 | `PascalCase` | `Show()`、`MainCamera` |
| 私有字段 | `camelCase` 或 `_camelCase`（同一文件内保持一致） | `_services`、`runner` |
| 局部变量 / 参数 | `camelCase` | `dt`、`uiEnum` |
| 常量 / `static readonly` | `PascalCase` | `DefaultAutoDestroyDelay`、`MaxSfxEmitters` |
| 枚举值 | `PascalCase` | `UILayerEnum.Normal` |
| 文件名 | 与文件内 **public 类型同名** | `UIMgr.cs` 含 `UIMgr` |

### 1.2 类型前缀策略

仓库历史上同时使用 `Y` / `YOTO` / `Got` / 无前缀，**新代码采用以下规则**：

- **框架核心服务**：无前缀 + `Mgr` 后缀 — `UIMgr`、`ResMgr`、`SoundMgr`、`StoreMgr`、`EventMgr`、`FlyTextMgr`。（相机服务历史命名为 `CameraManager`，是 `Manager` 后缀的唯一例外，重构时可统一。）
- **框架基础类型 / 抽象**：`Y` 前缀 — `YSceneBase`、`YStateMachine`、`YAStarManager`、`YSceneType`。
- **框架 UI 组件（继承 Unity UI）**：`YOTO` 前缀 — `YOTOButton`、`YOTOScrollView`、`YOTOUIShow`。
- **业务类**：无前缀，按用途命名 — `StartPanel`、`GameMainScene`、`TaskProgressSystem`。

历史名仍残留 `Got` 前缀的（如 A* 封装目录 `GotPathFinding/` 与 `GotAStarSeeker.cs` 等**文件名**——其中的类已改为 `YAStarSeeker`/`YAStarObstacle`/`YAStarLinker`，文件名待跟进对齐），按上述规则在重构时逐步统一。

### 1.3 命名空间

- 框架：`YOTO`（事件/资源/音频等核心模块）、`YFramework.Config`（配表）。
- 业务：当前未强制命名空间。**新代码请按目录起：** `Game.UI`、`Game.Scene` 等。
- 跨命名空间引用必须 `using` 显式导入，不要写 fully-qualified name。

### 1.4 文件命名

- 一个公共类型一个文件，文件名等于类型名（含大小写）。
- 例外：紧密相关的小型类型（`UIInfo` + `UIConfig` 同文件、`SoundChannel` + `SoundPlayOptions` + `SoundSettingsData` 同文件）允许合并。
- `.cs` 始终配对一个 `.meta`，连带提交。

## 2. 文件结构

每个 `.cs` 顶部按以下顺序：

```csharp
// 1. using - 系统命名空间在前，第三方/Unity 次之，本仓库自定义最后
using System;
using System.Collections.Generic;
using UnityEngine;
using DG.Tweening;
using YOTO;

// 2. namespace
namespace YOTO
{
    // 3. 嵌套类型/接口（与主类型耦合的）
    // 4. 主类型
    // 5. 文件级 partial 扩展
}
```

每个类内成员顺序：

```
1. 常量 / 静态字段
2. 实例字段（先 readonly 后 mutable）
3. 属性
4. 构造 / Init / Shutdown
5. Unity 生命周期（Awake / Start / Update / OnDestroy）
6. 公共方法
7. 私有方法
8. 嵌套类型（如未上提）
```

参考实现：`Framework/UI/UIMgr.cs`、`Framework/Sound/SoundMgr.cs`。

## 3. 注释

- **默认不写注释**。命名清楚 + 代码自解释优先。
- 写注释的场景：
  - 类型/服务对外契约（`<summary>` XML 注释，描述职责而非实现）。
  - 非显然的不变量、性能取舍、平台/Unity 特定 quirk。
  - 公共 API 的参数语义（如 `repeat: 0 表示无限循环`）。
- **不写**：复述代码、记录历史变更、写 TODO 当备忘（用 issue/任务系统）。
- TODO 必须含负责人或日期：`// TODO(name, 2026-05): 切换到 Addressables`。

示例（来自 `GameContext.cs`，正向案例）：

```csharp
/// <summary>
/// Initializes all registered services.
/// Keep this stage focused on dependency setup and subscriptions.
/// Avoid spawning scene content here.
/// </summary>
public void InitAll() { ... }
```

## 4. 服务、生命周期、依赖注入

### 4.1 实现 IGameService

任何需要 `Init` / `Shutdown` 的类都实现 `IGameService`，**不要** 用 `MonoBehaviour.Awake` 充当初始化入口（`MonoBehaviour` 由 `GameLoop` 单一持有）。

```csharp
public class FooMgr : IGameService
{
    private BarMgr bar;

    public void Init(GameContext ctx)
    {
        bar = ctx.Get<BarMgr>();      // 从容器解析依赖
    }

    public void Shutdown()
    {
        bar = null;                    // 清依赖、释放资源
    }
}
```

### 4.2 注册顺序

`GameBootstrapper.BuildContext` 内部按依赖顺序注册：被依赖的服务在前。例如 `ResMgr` 必须在 `UIMgr` 之前注册（`UIMgr.Init` 通过 `ctx.Get<ResMgr>()` 取它）。

业务服务通过 `partial` 方法 `RegisterProjectServices(ctx)` 注入，不要直接修改 `Framework/GameContext/GameBootstrapper.cs`。

### 4.3 帧调度

需要每帧执行的服务实现 `ITickable / IFixedTickable / ILateTickable`，由 `GameContext` 自动调度。**不要** 自己挂 `MonoBehaviour` 起 Update 循环。

```csharp
public class ScreenMonitor : IGameService, ITickable
{
    public void Tick(float dt) { ... }
}
```

### 4.4 协程

通过 `ICoroutineRunner` 启动协程，不要在普通服务里 `MonoBehaviour.StartCoroutine`：

```csharp
private ICoroutineRunner runner;
public void Init(GameContext ctx) { runner = ctx.Get<ICoroutineRunner>(); }

var co = runner.Run(MyRoutine());   // 启
runner.Stop(co);                    // 停
```

### 4.5 服务获取

- 服务内部：保存依赖的字段（在 `Init` 一次性 `ctx.Get<T>()`），后续直接用字段。
- UI 页面：`UIPageBase.GetService<T>()`（已注入 `Context`）。
- MonoBehaviour 临时获取：`GameLoop.Instance.Ctx.Get<T>()`，但避免在热路径调用。

## 5. 事件

- 全局事件走 `EventMgr`，不要直接 `Action` 静态字段或 `delegate`。
- 事件键为任意 `Enum`：业务枚举集中在 `GamePlay/Event/GameEventTypes.cs`（当前类型 `YOTOEventType`）。框架不持有具体业务枚举。
- 订阅与反订阅必须配对：UI 页面在 `OnShow` 订阅、`OnHide` 反订阅；普通服务在 `Init`/`Shutdown` 配对。
- 不要捕获 `this` 之外的临时变量到事件回调里，避免泄漏。
- 最多 4 个泛型参数（`EventMgr` 上限），更多参数请改成结构体一并传。

---

## 6. 资源加载

- **始终通过 `ResMgr`**，不要直接 `Resources.Load` 或 `AssetDatabase.LoadAssetAtPath`。
- 推荐：`LoadHandleAsync<T>(path, handle => ...)`。`ResourceHandle` 实现 `IDisposable`，支持 `using`。
- 所有 `Load*` 必须有对应的 `Release` / `Dispose`，否则计数泄漏。
- 加载失败统一 `Debug.LogError`，回调传 `null`，调用方判空。
- 不要在 `Update` 里反复 `LoadAsync` 同一资源；缓存 handle。

---

## 7. UI

- 页面继承 `UIPageBase` 或 `UIPageBase<TParam>`（含强类型参数）。
- 预制体必须挂 `CanvasGroup` + `YOTOUIShow`（`UIPageBase` 用 `RequireComponent` 强制）。
- 在 `GameProjectBootstrapper.ConfigureProjectUi` 注册：

```csharp
uiConfig.Register<MyPanel>(UIEnum.MyPanel, UILayerEnum.Normal, "UI/MyPanel");
```

- 显示：`Show<MyPanel>(param)`；隐藏：`CloseSelf()` 或 `Hide<MyPanel>()`。
- 生命周期回调：`OnLoad → BeforeShow → OnShow → OnHide → OnResize`。
  - `OnLoad` 一次性绑定（`Button.onClick.AddListener` 等）。
  - `OnShow` 订阅事件、刷新数据。
  - `OnHide` 反订阅事件、停 Tween。
  - `OnResize` 响应屏幕变化。
- 禁止在 `Awake/Start` 中获取业务服务，因为 `Initialize(context, manager)` 必须先调用（`UIPageHandler` 已保证调用序）。

## 8. 错误处理

- 系统/业务边界使用 `Debug.LogWarning`（可恢复）/ `Debug.LogError`（异常）。
- 日志统一前缀 `[ModuleName]`，方便过滤：

```csharp
Debug.LogError($"[ResMgr] Failed to load: type={typeof(T).Name}, path={path}");
```

- 不要 `throw new Exception("xxx")`；改为 `LogError + 安全 fallback`（返回 `null` / `false`），让调用方判空。
- `try/catch` 仅在以下场景：
  - 包装外部 IO（文件读写、网络解析）。
  - 资源解析（`UIPageHandler.OnLoaded` 包整段 try）。
- 不要吞异常：`catch(Exception e) { Debug.LogError(e); }` 至少留日志。

## 9. 性能

### 9.1 GC / 内存

- **避免** `Update` 内分配：闭包、`new List`、`string` 拼接、装箱（`int` → `object`）。
- 容器：复用 `List<T>` 字段，使用 `list.Clear()` 而非 `new List<T>()`。
- 字典遍历：使用 `Dictionary<,>.Enumerator` 避免装箱（参考 `Timers.Update`）。
- 字符串：热路径优先 `StringBuilder`；日志用插值（编译器优化为字符串拼接，仍有少量 GC，避免在每帧打）。

### 9.2 缓存

- `Camera.main`、`LayerMask.NameToLayer` 在 `Init` 时缓存，不在热路径反复取（如 `CameraManager.Init` 缓存 `SceneReferenceService`）。
- `GetComponent<T>` 在 `OnLoad` 一次性取，存字段。
- `Time.deltaTime` 直接使用 `Tick(dt)` 形参，不要重新拿 `Time.deltaTime`。

### 9.3 对象池

- 异步 GameObject：`AsyncPrefabPool` + `AsyncPooledObject` 子类（参考 `ParticleEntity`）。
- 同步 hot path GameObject：`PrefabPool<T>` + `IPoolable`。
- 纯数据：`DataObjectPool<T,S>`。
- 不允许在循环里 `Instantiate/Destroy`，全部走池。

### 9.4 协程 vs 帧调度

- 持续每帧的逻辑用 `ITickable`，不要起协程 `while(true) yield return null`。
- 一次性延迟用 `Timers.inst.Add(delay, 1, callback)`。
- 协程仅用于资源加载、动画序列、IO 等线性流程。

### 9.5 Update 频率

- 帧率限定 60FPS。`FixedUpdate` 默认 50Hz。
- 计时类（每秒一次的轮询）用 `Timers.inst.Add(1f, -1, ...)`，**不要** 在 `Tick` 里 `if (counter++ > 60)`。

## 10. Unity 特定约定

### 10.1 序列化

- 私有字段需序列化用 `[SerializeField]`，不要 `public` 暴露字段（除非确实是 Inspector 数据，如 `StartPanel.btn_new`）。
- 序列化的复杂结构标 `[Serializable]`（参考 `SoundSettingsData`）。
- 字典不可直接序列化。需要持久化字典 → 序列化为 `List<Entry>`（各业务 `*System` 的存档数据类即用此法，把 `Dictionary`/`HashSet` 拆成 `List` 存盘，读档时重建）。

### 10.2 MonoBehaviour 使用

- `GameLoop` 是仓库内 **唯一** 持久 `MonoBehaviour`（顶层）；UI 页面、池中对象这类与 GameObject 强绑定的类型才继承 `MonoBehaviour`（`AsyncPooledObject` 本身是纯 C# 基类，只持有实例化出的 GameObject）。
- 业务服务（玩家、敌人管理器等）一律 `IGameService`，不挂 `MonoBehaviour`。
- 切勿用 `GameObject.Find` / `FindObjectOfType` 在热路径里查找；用 `SceneReferenceProvider`。

### 10.3 编辑器扩展

- 放 `Assets/Scripts/Editor/`，仅在 `UNITY_EDITOR` 下可用。
- 自定义 `Inspector` 继承官方对应类（如 `YOTOButtonEditor : ButtonEditor`），调用 `base.OnInspectorGUI` 后再追加。

### 10.4 场景与 DontDestroyOnLoad

- `GameLoop`、`UIRoot`（`UIMgr.Init` 创建）、`SoundRoot`（`SoundMgr.Init` 创建）、`AsyncPrefabPool` 池根、`Timers` 内部 GO 自带 `DontDestroyOnLoad`。
- 业务不要再随意标 `DontDestroyOnLoad`，改用 `Framework/DontDestroy.cs` 组件。

---

## 11. 异步与多线程

- 项目目前 **不使用** `async/await`、不使用 `UniTask`。所有异步走协程 + 回调。
- 不要在协程里访问 Unity API 之外的线程对象；不要起 `Task.Run`。
- 文件 IO 走 `IStorageDriver`（默认 `FileStorageDriver` 实现，全部协程化，主线程友好）。

## 13. 代码评审要点

PR 评审重点关注：

1. **依赖方向**：是否破坏 Framework 不依赖 GamePlay。
2. **生命周期对称**：`AddListener`/`RemoveListener`、`Run`/`Stop`、`Load`/`Release`、`Subscribe`/`Unsubscribe`。
3. **Update 分配**：闭包、装箱、临时容器。
4. **资源路径**：是否硬编码字符串重复（推荐抽常量）。
5. **类名 / 文件名一致**。
6. **注释噪音**：删去无价值注释。

**涉及 Framework 改动的 PR 额外评审项**：逐条核对六条 Framework 设计原则（接口先行 / 向后兼容 / 职责单一 / 依赖方向单向 / 可池化可关闭 / 注册顺序），详见 [Docs/README.md「Framework 改动原则」](./README.md)。
