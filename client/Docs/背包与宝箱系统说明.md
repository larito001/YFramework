# 背包与宝箱系统说明

塔科夫/暗黑风格的 **2D 网格空间背包**:物品按形状(可不规则多边形)占一片格子,可拖拽、旋转、堆叠、合并、交换;
配套**宝箱**(概率掉落、首次开 roll、整局保持)与**背包↔宝箱互拖**;以及**世界掉落物**(丢弃 → 带模型落地 → 靠近按 F 捡回)。

数据全部走打表工具配表(protobuf),不使用 ScriptableObject。物品字段详见 [Item 配表说明](Item配表说明.md)。

## 二、核心模型 GridBag

固定 `Width`×`Height` 网格,一维占位表 `_occ`(0=空,否则=实例 id)做 O(占格数) 重叠检测。
坐标:x=列(向右),y=行(向下),锚点为形状包围盒左上格。物品定义通过构造时传入的 resolver 查询。

**关键 API**

| 方法 | 说明 |
|---|---|
| `TryAddItem(itemId, count)` | 加入若干个:可叠加先并堆再开新堆,返回放不下的剩余 |
| `TryAddItemAt(itemId, x, y, rot, count)` | 在指定锚点放一个新实例 |
| `PlaceOrSwap(instanceId, x, y, rot)` | 移动/合并/交换(同容器拖放落点),失败原位不动 |
| `RotateItem(instanceId)` | 顺时针 90°,原地放不下自动靠边夹回 |
| `SplitStack(instanceId, amount)` | 拆出新堆到空位 |
| `SortBag()` | 合并零散同种堆 + 按面积/权重降序紧凑重排 |
| `static Transfer(from, id, to, x, y, rot)` | **跨容器转移**(背包↔宝箱) |
| `RemoveItem` / `GetByInstance` / `GetAt` / `CountItem` / `CanPlace` | 查询与移除 |
| `ToSaveData` / `LoadFromSaveData` | 存档 |

**事件**:任意变化触发 `OnChanged`;`BagGridView` 订阅它自刷新,`BagSystem` 桥接到 `EventMgr.RefreshBagList`。

### 重点行为约定

- **合并**:拖到同种可叠加且未满的物品上 → 合并,超上限的留原位。
- **交换**:拖到唯一异物上 → 两者交换;**对方落位在「本物品已就位」的网格上判定**,避免拖动距离小于物品尺寸时两者共格重叠。交换不干净则整体回滚。
- **整理**:可叠加物品先按 itemId 合并总量,再按占格面积降序 → SortPriority 降序 → id 重排;超单堆上限拆多堆。
- **跨容器转移**:先试目标锚点精确落位,失败则自动并堆/找空位;部分转移正确扣量,一个都放不下则源不变。

## 三、玩家背包 BagSystem

`IGameService`,默认网格 10×8。`Init` 建背包、读配表、异步读档;**面板关闭时存档**(`GridHostPanelBase.CommonHide` 调 `Save`,可靠);`Shutdown` 也调 `Save` 但仅尽力而为(退出时异步写盘协程可能来不及)。

```csharp
var bag = ctx.Get<BagSystem>();
bag.AddItem(3001, 80);          // 放入 80 个铁矿石(超单堆上限自动分多堆)
bag.GetItem(id);                // 配表 Item
bag.GetItemType(id);            // ItemType
bag.GetItemQuality(id);         // ItemQuality(决定格背景色)
bag.UseItem(instanceId);        // 使用(消耗品成功后扣 1)
bag.Discard(instanceId);        // 丢弃:移出背包 + 经 DropItemSystem 在玩家身前生成可拾取掉落物(任务物品受保护不可丢)
bag.SortBag();
bag.Bag;                        // GridBag 实例(UI 渲染它)
```

**使用逻辑**:消耗品效果实现 `IItemUseHandler`,以物品 id 为键 `RegisterUseHandler` 注册(见 `HealItemUseHandler`)。

**存档**:走框架 `StoreMgr`(`BagDataContainer` + 异步 JSON 文件,落盘 `persistentDataPath/BagSave.json`),只存 实例 id/物品 id/坐标/朝向/数量(物品定义不存,读档按配表重算)。读写均异步;**存档点是面板关闭**(此后有帧让写盘协程跑完),不能只依赖 `Shutdown`(退出时协程不再恢复会丢档)。

## 四、宝箱

### 配表(两张,生成流程同 Item 配表说明)

- `chest`:宝箱本体(id / name / 网格宽高 / `groupSeq` 掉落组序列 / `rollSeq` 抽取次数序列)
- `chestDrop`:掉落条目(groupId 分组 / itemId / weight 权重 / minCount~maxCount 数量范围)

`groupSeq[i]` + `rollSeq[i]` 平行数组,按开启次序 i 取:用该组掉落、加权抽 rolls 次,每条按数量范围随机放入。

### 刷新策略

**首次打开 roll 一次,整局保持,游戏重开刷新**:
- `ChestSystem.Roll(chestId, openIndex)` 是工厂,生成新 `GridBag`,不缓存。
- `ChestEntity` 首次打开调 `Roll` 存自身 `rolledGrid`,之后复用(玩家拿走/放入都留在它上面)。
- **不写盘**,游戏重开 → 实例重建 → 重新 roll。

### 世界交互

- `IInteractable` 接口:`WorldPosition` / `InteractRange` / `Prompt` / `CanInteract` / `Interact()`。
- `WorldInteractionSystem` 每帧找最近、在范围内的可交互物,显示提示("按 F 打开宝箱"),按 **F**(`InputService.OnInteractWorldDown`)触发。
- `ChestEntity.Interact` → roll(首次)+ `ChestSystem.SetCurrent` + `UIMgr.Show<ChestPanel>()`。

> ⚠️ 服务注册顺序:`WorldInteractionSystem.Init` **只订阅 F 键**(InputService 在它之前注册),`CharacterManager`/`ViewManager` 在 Tick 里懒取——避免 Init 硬取后注册的服务抛异常导致 F 键没订阅上。

## 五、掉落与拾取(丢弃 → 落地 → F 捡回)

丢弃物品时不再凭空消失,而是在世界生成一个**带模型、会落地、可拾取**的掉落物。复用宝箱同一套世界交互框架(`IInteractable` + `WorldInteractionSystem` 靠近检测 + F 触发)。

### 流程

1. UI 右键菜单「丢弃」→ `BagSystem.Discard(instanceId)`:任务物品(`QuestItem`)拦截;否则先抓 itemId/count/rotation,再从背包移除,最后调 `DropItemSystem.DropAtPlayer`。
2. `DropItemSystem.DropAtPlayer` 在**玩家身前**(身前 1.2m + 抬高 1m)生成掉落物,给一点向前上方初速度,靠 `Rigidbody` 重力**落到地面**。
3. 玩家靠近 → `WorldInteractionSystem` 显示「按 F 捡起 {名称} x{数量}」→ 按 **F** → `DropItem.Interact` 调 `BagSystem.AddItem` 放回背包:全进了销毁本体,背包满则把放不下的剩余留在地上。

### 模型(当前为占位)

按**品质上色的 box 预制体**占位:`Resources/Item/Prefabs/DropBox_<品质>`(5 个品质各一个,由菜单 **Tools/Bag/Build Item Drop Prefabs** 生成;材质在 `Art/Item/DropBox_<品质>.mat`,URP/Lit、按 GUID 引用——材质不必进 Resources)。`DropItemSystem` 按物品品质 `Resources.Load` 对应预制体并实例化,再按配表 `Width/Height` 缩放。预制体缺失(没跑生成菜单)时退回运行时拼一个上色 cube,不崩。

> **接真实模型**:把对应 prefab 换成真模型即可;或给 item 配表加 `modelPath` 列、重发布,改 `DropItemSystem.BuildModel` 走 `cfg.ModelPath`,丢弃/拾取逻辑不动。

### 通用掉落 API(不止丢弃)

`DropItemSystem` 是"把物品丢到世界"的统一入口,其它掉落来源(怪物死亡、宝箱溢出、关卡预放、奖励)都可复用:

```csharp
var drop = ctx.Get<DropItemSystem>();
drop.DropAtPlayer(itemId, count);   // 玩家身前丢出(Discard 走这个)
drop.Spawn(itemId, count, worldPos); // 世界任意位置生成,返回 GameObject
```

> 掉落物放在 `Ignore Raycast` 层:照常落地碰撞,但不被子弹等射线误中(拾取走距离检测,不走射线)。
> 注册顺序:`DropItemSystem` 在 `WorldInteractionSystem` 之后注册;`BagSystem.Discard` 懒取它(`BagSystem` 注册更早)。

## 六、UI 交互一览

| 操作 | 效果 |
|---|---|
| B 键 | 开/关背包(`BagSystem` 监听 `InputService.OnToggleBagDown`);开背包前自动关宝箱面板 |
| F 键 | 靠近宝箱时打开宝箱面板;靠近掉落物时捡回背包(`WorldInteractionSystem` 统一分发) |
| 左键单击 | 无(不直接使用;使用走右键菜单) |
| 左键双击 | (宝箱面板)快速转移到另一面板 |
| 右键单击 | 打开菜单:使用 / 旋转 / 拆分 / 丢弃 |
| 拖拽 | 移动 / 合并 / 交换 / 跨容器转移;实时绿(可放)红(不可放)落点高亮,落点按物品左上角对齐 |
| 悬停 | tooltip:名称(品质色)/ 描述 / 预估价值 |
| 整理按钮 | 紧凑重排 |

**品质背景色**:普通灰 / 优秀绿 / 稀有蓝 / 史诗紫 / 传说橙(集中在 `ItemQualityPalette`)。

**互斥**:`ChestPanel` 自带左侧背包,打开时 `Hide<BagPanel>()`,避免两个背包 UI 重叠。

## 七、接入清单(新场景/新宝箱)

1. **打开背包**:`ctx.Get<UIMgr>().Show<BagPanel>()`。
2. **放宝箱**:实例化宝箱模型预制体,挂 `ChestEntity`,设 `chestId`(对应 chest 配表)、`interactRange`。
   `WorldInteractionSystem` 自动接管靠近检测 + F 打开(参考 `GameStartScene.SpawnChests`:随机品质 + y 抬高 0.5)。
3. **改物品/宝箱数据**:编辑 `tools/excel/3xlsx/` 下对应 xlsx(先关 Excel),双击 `tools/build_tables.bat` 一键发布,回 Unity 编译。
4. **UI 布局/配色**:改 `BagPrefabBuilder` 后**重跑 Tools/Bag/Build Bag UI Prefabs**(布局是生成时写死的)。

## 八、扩展点

- **新使用效果**:实现 `IItemUseHandler`,`bag.RegisterUseHandler(itemId, handler)`。
- **新物品形状**:配表 `shape` 掩码(如 `"10|11"` L 形),无需改代码。
- **新品质**:`ItemQuality` 枚举 + `ItemQualityPalette` 配色,各补一项。
- **新可交互物**(非宝箱):实现 `IInteractable` + 注册到 `WorldInteractionSystem`,即可复用靠近+F 框架。
- **新双网格界面**(如商店):继承 `GridHostPanelBase`,声明两个 `BagGridView` 并 Bind,拖拽/转移逻辑自动复用。
- **新掉落来源**(怪物死亡 / 宝箱溢出 / 关卡预放 / 奖励):调 `DropItemSystem.Spawn(itemId, count, pos)`,落地 + F 拾取逻辑自动复用;"掉什么"的规则建议走配表(如新开掉落表),勿硬编码。
- **掉落物换真实模型**:item 配表加 `modelPath` 列,只改 `DropItemSystem.BuildModel` 一处。

## 九、已知约束

- 宝箱内容不写盘(整局内存保持),重开即重 roll —— 符合当前设计。
- **掉落物不写盘、无回收上限**:退出重进消失;一直丢不捡会在地上累积(每个带 Rigidbody),量大伤性能。需要时再加持久化 / 数量上限 / 定时消失。
- **掉落物模型为占位**:按品质上色的 box,尺寸随 `Width/Height`,接真实模型见扩展点。
- 网格 UI 尺寸在 `BagPrefabBuilder` 里按格数像素硬算(cell 80px):背包 10×8、宝箱默认 8×6。改格数需同步调窗口尺寸,否则可能溢出。
- 物品左上名称在 1×1 小格会压住图标上部(设计取舍)。
